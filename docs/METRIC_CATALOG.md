# 净入金指标目录（第一批）

代码入口：`src/fitzsight/metrics/catalog.py`。`get_metric` 只接受完整、精确、带版本的白名单 ID；未知 ID、无版本或新版本不自动回退。不可变 `MetricDefinition` 通过 `to_dict()` 导出独立 JSON 快照，调用者修改快照不会修改目录。

| ID | 公式 | 分母 | 单位 |
|---|---|---|---|
| `net_deposits.v1` | 当期 completed 存款金额之和 − 当期 completed 提款金额之和 | 无 | USD 金额 |
| `net_deposit_change.v1` | 本期净入金 − 基线净入金 | 无 | USD 金额 |
| `net_deposit_decomposition.v1` | (本期存款−基线存款) − (本期提款−基线提款) | 无 | USD 金额 |

分解同时保留存款变化和提款变化；这三项不是百分比、收益率或人均金额。实现仍为确定性 Python/SQL，不执行目录公式字符串。新增版本须同时修改执行器、独立核验与测试，不能只改描述字符串。

口径：按流水 `timestamp` 归属期间，开始日包含，结束日下一日排除；使用源数据无时区时间，不自动转换。状态只计 `completed`；选中非 USD 流水拒绝，不换汇。地区来自当前客户表 `customers.region`，经 `customer_id` 内连接，不能冒充历史客户归属。

流水键声明为 `deposits.deposit_id` / `withdrawals.withdrawal_id`；**当前不按键去重，也未强制唯一性**，仍是连接后逐行求和。目录显式记录该政策，不把声明的键当成完成的质量约束。M2 仍需主键/外键、重复/晚到/撤销、金额定点、快照及对账验证。

净入金是资金流，不是投资收益、余额或流动性。当前 schema 未独立识别内部划转，不能声称已经计算“严格排除内部划转的外部资金流”。该业务改造留待 M2/M3，届时应建立新版本及相应数据契约。

## 证据与兼容性

引擎将三项定义写入 `net_deposit_driver_decomposition` 证据的 `parameters.metric_definitions`，随调查结果中的 evidence 导出。N-C1/N-C2 从目录读取单位/币种，并要求证据定义完整匹配批准版本；删除、重复、缺项或改写定义都会拒绝。数值仍独立从四份来源结果重算，定义一致不能替代金额检查。

旧的、没有定义快照的 N-C1/N-C2 证据不会被新核验器自动赋予版本；应在对应代码与数据下重新执行，历史原始记录保留。现有测试夹具已补合法定义，旧错数字、单位、日期和引用反例继续执行。

范围：目前仅覆盖上述三个净入金金额定义及 N-C1/N-C2；集中度、人均指标、其他意图目录和 UI 展示尚未迁移。InvestigationRequest、请求白名单、三个地区/三组时期和 demo 配置分离仍待完成。参数真实性、源 SQL 正确性/完整性、行数上限、持久化签名和真实数据质量仍是独立边界，不因定义匹配自动验收。
