# 数值声明迁移：净入金变化与分解契约

本轮只覆盖净入金调查的 **N-C1、N-C2、N-C3、N-C4**，不是所有报告数字都已经核验。N-C5 已增加独立事件事实契约（见下文）；转化率、营销和分群声明仍沿用旧检查；M1-02 总项保持进行中。

`Claim.numeric_binding` 对 N-C1/N-C2 必须存在，包含指标标识 `net_deposit_change.v1`、数值、金额单位、USD、Europe、四个日期边界和证据 ID/字段。旧 Claim 可不带绑定，以支持逐条迁移，但净入金计划必须分别恰有一个 N-C1 和 N-C2，不能通过删掉绑定/声明逃过检查。

当前契约固定为合成演示的 USD、Europe 和现有日期口径，未实现通用 MetricDefinition 或跨地区/时期请求。文字由 `render_net_change` 统一生成；核验器要求文字与绑定渲染完全一致，避免结构化值正确而自由文字写错。

核验步骤：

1. 确认绑定类型、指标/字段/单位/币种/区域白名单，以及有限且非布尔的数值。
2. 确认证据引用、工具类型、成功状态及现有结果摘要。
3. 与分解证据中的金额、币种、区域及四个时间边界比较。
4. 从四份原始 SQL 结果按 baseline deposit/withdrawal、current deposit/withdrawal 顺序重算 `(current deposits - current withdrawals) - (baseline deposits - baseline withdrawals)`，并检查四份引用及摘要。
5. 用绝对容差 1e-8、相对容差 0 比较未格式化金额；呈现保留两位小数。模板文字也必须一致。

净入金的现金流查询现在读取 currency，遇非 USD 直接拒绝，不把其他币种金额静默标成美元。该检查不实现汇率换算。

## 验证与边界

[RUN-05](validation/2026-10-27-run05.md) 记录手算小样本、数值/单位/币种/日期/字段/引用篡改、中文错误文字、绑定/声明删除和错误分解重算反例，以及实际引擎回归。Mock 的非 USD 拒绝测试只证明分支行为，不代表真实外部数据接入。

证据工具和执行代码仍是信任边界：当前摘要不是签名，参数没有独立不可篡改保护；此核验不证明 SQL 符合请求、未截断、原始流水没有重复、财务状态定义正确或数据快照可信。重算来自工具结果，不是重查源数据。时区、金额定点化、快照和数据契约仍待后续 M1/M2/M4；一般性的“合法 ID + 错数字”P0 尚未整体关闭。

## N-C5 事件措辞边界（RUN-20261028-11）

N-C5仅陈述欧洲、指定事件类型、附近半开时间窗口内是否检索到运营日志。未匹配时输出“未找到”，并明确这不证明现实中没有事件；匹配时也不把日志单独当作提款驱动或原因的证据。空日志、类型/地区/窗口不符以及存在事件但现金流全零的合成CSV在两个后端实际导入测试。

本次只修复引擎生成的文字；verifier尚未独立重算N-C5事件匹配、检查唯一声明或拒绝事后篡改。M1-02b-4b保持待办，不能将报告的verified状态解释为N-C5完整事实契约通过。


## N-C5 独立事实契约（RUN-20261028-12）

EventBinding绑定地区、类型、半开日期窗口、匹配事件ID及SQL来源；verifier要求恰有一个N-C5，从完整结果逐行重新筛选并核对有序ID、状态、置信度和规范文字。缺绑定、重复/删除声明、错来源/文字/窗口、同步伪造“未找到”及截断/预览/损坏日志均失败关闭。上一批“尚未独立核验”是当时状态，已由本批替代。

当前契约限定Europe、HIGH_VALUE_WITHDRAWAL_CLUSTER、2026-08-03至2026-08-08（不含）。只接受当前批准查询；不是通用SQL语义验证器。来源SQL执行、注册器真实性与日志完整性仍是信任边界；摘要不签名参数，不能防止攻击者同时伪造整个注册器。事件事实不等于客户动机或因果；不独立验证整个diagnosis对象。参数化仍待M1-01，持久化审计待M4。

N-C1/N-C2 现在要求驱动证据携带批准的[净入金指标目录](METRIC_CATALOG.md)定义快照；缺失或被改写时拒绝。旧数值重算、文字、窗口、单位和币种核验保留。旧证据不静默补版本，需要重新执行；目录声明的流水键尚不代表已执行去重或导入质量检查。

## RUN-21：N-C1/N-C2 来源完整性

净入金金额计算和两个金额声明的独立核验现在要求SQL来源明确包含 `truncated: false`、完整 `rows` 列表和与列表长度相等的整数 `row_count`。缺失标记不视为完整；字符串/整数冒充布尔、布尔冒充行数、compact preview或预览标记均拒绝。旧手工证据若缺这些元数据须重新执行，不静默放行。

任一基线/本期的存款/提款明细查询达到工具截断条件时，引擎在产生driver decomposition前报错；原SQL证据保留截断状态供诊断。恰好等于max_rows且未截断，以及合法空查询，仍可计算。此批没有提高行数上限、禁用截断或将部分结果冒充全量。

这些检查证明工具所报告结果完整性符合契约，不证明SQL过滤条件、JOIN完整性、源数据真实性或未被恶意重写的注册器。N-C3/N-C4的独立完整性检查仍需专项复核；引擎的金额入口保护不能代替所有下游/离线核验。大数据量应后续使用可核验的聚合或分批策略，本次只失败关闭。

## RUN-22：N-C3/N-C4 来源完整性补齐

N-C3的当前提款明细、N-C4的四份区域SQL汇总现在复用RUN-21的 `complete_sql_rows`：必须有明确未截断标记、完整rows及匹配的整数行数，拒绝预览和缺失元数据。检查在独立核验器内执行，不依赖上游引擎曾检查。区域计算入口也在使用结果前拒绝不完整查询；不把少了某地区的截断结果当作完整对照组。

RUN-21所记N-C3/N-C4待复核项在此范围解决。合法空明细、零分母和缺目标/对照地区的证据不足状态保留；缺元数据的旧手工证据需要重新执行。仍不证明SQL过滤/JOIN、聚合前源数据完整性或注册器真实性，也不是三条业务链的全部结果核验。N-C5原有截断/预览保护不由此扩张为通用数据质量验收。

## RUN-23：请求金额阶段

N-C1/N-C2增加显式`expected_request`核验入口；新金额服务只输出这两条声明，不包装为完整调查通过。除既有重算/完整性规则外，检查可信请求、批准SQL和绑定参数一致；金额模板改用实际地区和期间，不再无条件写European/week over week。旧固定场景的其他声明及核验要求不变。使用方法与边界见[请求契约](INVESTIGATION_REQUEST.md#请求驱动金额执行run-23)。


### N-C5来源完整性补充（RUN-20261030-26）

事件事实核验复用金额/区域的完整SQL行判定：明确未截断、整数行数与完整字典行一致，且不得带evidence_mode或rows_preview标记。即使另有rows且摘要有效，也不能将预览证据作为完整匹配/无匹配的依据。引擎遇到截断结果时在事件匹配与最终结果生成前拒绝；空且完整的日志仍输出证据不足。真实日志是否完整、来源是否真实仍是信任边界；本批不提供分页、N-C5参数化或持久化防篡改。
