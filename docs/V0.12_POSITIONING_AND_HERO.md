# FitzSight v0.12 — Positioning and Hero Workflow

## Primary persona

**Primary:** Brokerage / FinTech Operations Analyst  
**Secondary:** Regional Operations Manager / Sales Operations Manager

The beachhead workflow is internal financial-operations investigation across the chain:

```text
acquisition → FTD conversion → client-fund flows
```

FitzSight is not positioned as a consumer investment adviser, an autonomous risk decision-maker, or a generic “chat with data” interface.

## Competition promise

> **Autonomous investigation. Human decision.**

The system may autonomously investigate an approved operational question, choose the next action from a bounded action catalog based on observed tool results, and produce an evidence-linked decision-support brief. The business decision remains with an authorized human.

## Hero workflow — CRM / FTD deterioration

The primary judge-facing journey is:

```text
Question
→ bounded plan
→ affected/control measurement
→ statistical validation
→ team contribution decomposition
→ result-driven latency drilldown
→ result-driven operational-event check
→ source-paragraph document evidence
→ EvidenceClaimVerifier
→ verified answer / guardrail
→ approved follow-up
```

The conditional steps remain bounded. The planner cannot generate arbitrary SQL, table names, filesystem paths, tool parameters, or high-impact financial actions.

## Failure / insufficient-evidence branch

If the contribution/statistical trigger is not met, FitzSight skips the deeper attribution branch. If the operational-event dependency fails, the failure is recorded in the audit registry and the root-cause status becomes `insufficient_evidence`; FitzSight does not “fill in” the missing context.

`tests/test_v12_hero_journey.py` covers both the normal hero path and the event-tool failure path.

## Real product-process evidence

The v0.12 build includes runtime-derived judge-facing assets:

- `docs/V0.12_HERO_RUN.json`
- `submission/FitzSight_Hero_Run_Evidence.html`
- `submission/FitzSight_Hero_Run_Evidence.png`

They are generated from a real deterministic Agent run, not hand-authored analytical values. The view contains the user question, bounded execution trace, Evidence IDs, verifier status, final answer/guardrail, approved follow-up, and source-paragraph document evidence.
